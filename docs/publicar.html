A Chave da Virada · IASD Nova Esperança · Caxias do Sul

Como colocar o site no ar

Nove passos, cerca de 40 minutos, sem programar. Tudo o que é conta, chave ou senha fica com você — nada passa pelo chat. Faça na ordem.

Você precisa deo arquivo chave-da-virada.zipum e-mailo domínio igrejaadventista.ia.br (já é seu)

Parte 1 — O banco de dados (Supabase)

1

Criar o projeto

Entre em supabase.com → Start your project → crie a conta com seu e-mail. Clique em New project:

  • Name: chave-da-virada
  • Database password: invente uma senha forte e anote (não é usada no site, mas o Supabase pede)
  • Region: South America (São Paulo)
  • Plano: Free

Espere 1–2 minutos até o projeto ficar verde.

2

Criar as tabelas (dois arquivos SQL)

No menu da esquerda, SQL Editor → New query. Abra, no seu computador, o arquivo supabase/migrations/0001_fundacao.sql (está dentro do zip), copie todo o conteúdo, cole no editor e clique Run. Deve aparecer Success.

Repita com supabase/migrations/0002_licoes.sql (ele carrega as 20 lições, a função de pontos e a coluna da sessão do site).

Se der erro em 0001 dizendo que algo "already exists", é porque rodou duas vezes — pode seguir.

3

Copiar as três chaves

Project Settings (engrenagem) → API. Deixe esta aba aberta; você vai colar na Vercel:

  • Project URL → vira NEXT_PUBLIC_SUPABASE_URL
  • anon public → NEXT_PUBLIC_SUPABASE_ANON_KEY
  • service_role (clique em Reveal) → SUPABASE_SERVICE_ROLE_KEY — esta é secreta: nunca cole no chat, em grupo ou no Framer.

Parte 2 — O código (GitHub)

4

Subir o projeto para um repositório

Entre em github.com → crie a conta se não tiver → New repository: nome chave-da-virada, Private, Create repository.

Descompacte o zip numa pasta. Na página do repositório vazio, clique em uploading an existing file, arraste todo o conteúdo da pasta (inclusive as pastas src, supabase, public, scripts, docs e os arquivos soltos) e clique Commit changes.

Mais fácil ainda: instale o GitHub Desktop, Add local repository apontando para a pasta, e Publish repository.

Não suba a pasta node_modules nem um arquivo .env com chaves (o zip não tem nenhum dos dois).

Parte 3 — O site no ar (Vercel)

5

Importar e configurar

Entre em vercel.com → Sign up with GitHub → Add New… → Project → escolha chave-da-virada → Import. Antes de clicar em Deploy, abra Environment Variables e adicione, uma por uma (nome à esquerda, valor à direita):

NEXT_PUBLIC_SITE_URL = https://igrejaadventista.ia.br NEXT_PUBLIC_WHATSAPP_NUMERO = 5554999773000 NEXT_PUBLIC_SUPABASE_URL = (Project URL do passo 3) NEXT_PUBLIC_SUPABASE_ANON_KEY = (anon public do passo 3) SUPABASE_SERVICE_ROLE_KEY = (service_role do passo 3) CRON_SECRET = (invente 30 letras e números, ex.: senha gerada) AVISO_WHATSAPP = 5554999773000 AVISO_WEBHOOK_URL = (deixe vazio por enquanto; ver passo 7)

Clique Deploy. Em 2 minutos aparece Congratulations com um endereço do tipo chave-da-virada.vercel.app. Abra e teste: a página inicial, a lição 1, o chat com a Esperança, o pedido de oração e /certificado/CV-DEMO.

Enquanto o domínio não estiver pronto, troque NEXT_PUBLIC_SITE_URL pelo endereço .vercel.app (Settings → Environment Variables → editar → Redeploy).

6

Domínio igrejaadventista.ia.br (já é seu)

Na Vercel: Settings → Domains → Add → digite igrejaadventista.ia.br e, em seguida, www.igrejaadventista.ia.br (marque para redirecionar o www para o principal). A Vercel mostra dois registros DNS:

  • Tipo A, nome @, valor 76.76.21.21
  • Tipo CNAME, nome www, valor cname.vercel-dns.com

Domínios .ia.br são do registro.br: entre com sua conta → o domínio → Editar zona DNS → Modo avançado, crie esses dois registros, salve. Se o domínio hoje aponta para outro lugar (um site antigo), esses registros substituem os antigos de @ e www. Entre 10 minutos e algumas horas o site responde no domínio com cadeado (HTTPS automático). Então volte à Vercel e deixe NEXT_PUBLIC_SITE_URL = https://igrejaadventista.ia.br → Redeploy.

7

Receber os pedidos de visita por e-mail (até o WhatsApp oficial existir)

O site avisa a igreja quando alguém pede visita. Sem a API do WhatsApp, o jeito gratuito é um webhook que vira e-mail:

  • Crie conta em make.com (plano Free) → Create a new scenario.
  • Primeiro módulo: Webhooks → Custom webhook → Add → copie a URL gerada.
  • Segundo módulo: Email → Send an email (ou Gmail) para o e-mail da coordenação; no assunto use {{assunto}} e no corpo {{texto}}.
  • Ative o cenário (botão ON) e cole a URL em AVISO_WEBHOOK_URL na Vercel → Redeploy.

Teste: no site, peça uma visita pela Esperança. O e-mail deve chegar em segundos.

Parte 4 — Depois (quando houver tempo)

8

WhatsApp oficial da Esperança (Meta Cloud API)

Precisa do número da igreja (um chip que não esteja em nenhum WhatsApp) e de uma conta Meta Business. Em developers.facebook.com: Create App → Business → WhatsApp. Em API Setup: adicione o número, copie o Phone number ID e gere um token permanente (System User). Em Configuration → Webhook:

Callback URL: https://igrejaadventista.ia.br/api/whatsapp/webhook Verify token: (a mesma string que você colocar em WHATSAPP_VERIFY_TOKEN) Campo a assinar: messages

Na Vercel, adicione WHATSAPP_PHONE_NUMBER_ID, WHATSAPP_ACCESS_TOKEN, WHATSAPP_VERIFY_TOKEN e WHATSAPP_APP_SECRET (App Settings → Basic → App Secret) → Redeploy. A partir daí a Esperança responde no WhatsApp e os avisos de visita chegam no número de AVISO_WHATSAPP.

9

Vitrine no Framer

No site do Framer (gold-baguette-236875.framer.app), aponte os botões para o app: Quero conversar → https://igrejaadventista.ia.br/conversar; curso → /curso; oração → /oracao. Ou use o próprio app como site principal e esqueça o Framer — ele já tem a página inicial completa.

Checagem final

Problemas comuns: "Supabase não configurado" = faltou uma das três chaves ou não fez Redeploy. Erro 500 no chat = o SQL 0002 não foi rodado (falta a coluna sessao_site). Build falhou na Vercel = subiu a pasta node_modules; apague do repositório.
